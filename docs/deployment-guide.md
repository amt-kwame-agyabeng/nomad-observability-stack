# Deployment Guide

## Purpose

This guide describes how the Nomad observability stack was deployed in the local WSL Ubuntu environment.

## Prerequisites

- Windows with WSL and Ubuntu.
- Docker Engine installed and running.
- HashiCorp Nomad installed.
- Nomad Docker task driver available.
- Project files at `~/projects/nomad-observability-stack`.

Check installed versions:

```bash
nomad version
docker version
```

## 1. Open the project directory

```bash
cd ~/projects/nomad-observability-stack
```

## 2. Start the Nomad development agent

```bash
nomad agent -dev -config=/home/kwamzzy/nomad-dev.hcl
```

Keep the agent running in its terminal. The lab configuration enabled Docker volume support and selected the WSL `eth0` network interface.

Nomad UI: `http://127.0.0.1:4646`

> Development mode is for local testing. Restarting the dev agent can clear its state, so jobs may need to be submitted again.

## 3. Validate and deploy the jobs

Run these commands from the repository root. The job names below match the jobs used in this lab.

### Nginx

```bash
nomad job validate nomad/nginx.nomad
nomad job run nomad/nginx.nomad
nomad job status nginx
```

Open `http://172.18.49.163:8080` and confirm the Nginx page loads.

### Node Exporter

```bash
nomad job validate nomad/node-exporter.nomad
nomad job run nomad/node-exporter.nomad
nomad job status node-exporter
```

Open `http://172.18.49.163:9100/metrics` and confirm metrics are returned.

### Prometheus

```bash
nomad job validate nomad/prometheus.nomad
nomad job run nomad/prometheus.nomad
nomad job status prometheus
```

Open `http://172.18.49.163:9090/targets` and verify the configured targets are `UP`.

### Loki

```bash
nomad job validate nomad/loki.nomad
nomad job run nomad/loki.nomad
nomad job status loki
curl http://172.18.49.163:3100/ready
```

The readiness endpoint should return `ready`.

### Grafana

```bash
nomad job validate nomad/grafana.nomad
nomad job run nomad/grafana.nomad
nomad job status grafana
```

Open `http://172.18.49.163:3000`. The lab used temporary local credentials `admin` / `admin123`. Change them before exposing Grafana beyond a trusted local environment.

### Grafana Alloy

```bash
nomad job validate nomad/alloy.nomad
nomad job run nomad/alloy.nomad
nomad job status alloy
```

Open `http://172.18.49.163:12345` and check that Alloy's UI is available and its configuration is loaded.

## 4. Verify the deployment

List jobs:

```bash
nomad job status
```

Inspect a job and allocation:

```bash
nomad job status <job-name>
nomad alloc status <allocation-id>
nomad alloc logs <allocation-id>
```

Prometheus query:

```promql
up
```

Loki query in Grafana Explore:

```logql
{job="docker"}
```

Generate test Nginx requests:

```bash
for i in {1..10}; do
  curl -s -o /dev/null http://172.18.49.163:8080
done
```

Filter Nginx GET requests generated by curl:

```logql
{job="docker", container=~".*nginx.*"} |= "\\\"GET " |= "curl/"
```

## 5. Update the host IP if it changes

The lab used `172.18.49.163`, the WSL IP at the time. If WSL assigns a different address, update the corresponding host references in `prometheus/prometheus.yml`, `grafana/provisioning/datasources/datasources.yml`, `grafana/config.alloy`, and any Nomad job file that explicitly uses the host IP. Redeploy or restart affected jobs as appropriate.
